# TeenC++ 产品设计工作流 - 产出物归档规范

**版本**: 1.0  
**日期**: 2026-04-06  
**适用范围**: L01/L02三阶段重构及后续课程设计

---

## 1. 目录结构规范

### 1.1 基础路径

所有设计文档统一存储在项目根目录下的 `docs/design/` 中：

```
TeenagerCPlusPlusEduSystem/          # 项目根目录
├── docs/
│   └── design/                      # 设计文档根目录
│       ├── research/                # Phase 1: 调研分析
│       ├── concept/                 # Phase 2: 概念设计
│       ├── prd/                     # Phase 3: 详细设计
│       ├── review/                  # Phase 4: 评审验证
│       ├── DESIGN_SYSTEM.md         # 设计系统规范
│       └── DESIGN_WORKFLOW_GUIDE.md # 本文件
└── ...
```

### 1.2 各Phase目录命名规则

| Phase | 目录名 | 文件命名模板 | 示例 |
|-------|--------|--------------|------|
| Phase 1 | `research/` | `{项目代号}_research.md` | `L01_L02_research.md` |
| Phase 2 | `concept/` | `{项目代号}_concept.md` | `L01_L02_concept.md` |
| Phase 2 | `concept/` | `{项目代号}_concept_{role}.md` | `L01_L02_concept_architect.md` |
| Phase 3 | `prd/` | `{项目代号}_prd.md` | `L01_L02_prd.md` |
| Phase 4 | `review/` | `{项目代号}_review.md` | `L01_L02_review.md` |

### 1.3 项目代号规范

- 格式: 大写字母+数字，用下划线连接
- 课程设计: `L{课程号}` 或 `L{课程号}_{主题}`
- 示例: `L01_L02`, `L04_Loops`

## 2. 四阶段工作流产出物清单

### Phase 1: Research 调研分析

**负责 Agent**: Researcher

**输入**:
- 现有课程 lesson.json
- 用户反馈数据
- 竞品课程样本

**产出物**:

| 文件 | 路径 | 内容要求 |
|------|------|----------|
| 调研报告 | `docs/design/research/{代号}_research.md` | 现状分析、竞品对比、用户洞察 |
| 数据支持文件 | `docs/design/research/data/` | 原始数据、截图、引用链接 |

**质量检查清单**:
- [ ] 包含现状问题列表（至少3个）
- [ ] 包含竞品分析对比表
- [ ] 引用来源明确标注
- [ ] 提出具体设计建议

---

### Phase 2: Concept 概念设计

**负责 Agent**: Architect + Storyteller

**输入**:
- Phase 1 调研报告
- L03 参考设计

**产出物**:

| 文件 | 路径 | 内容要求 |
|------|------|----------|
| 概念设计合并版 | `docs/design/concept/{代号}_concept.md` | 关键决策汇总、执行摘要 |
| 架构设计 | `docs/design/concept/{代号}_concept_architect.md` | 数据模型、API设计、技术选型 |
| 故事设计 | `docs/design/concept/{代号}_concept_storyteller.md` | 世界观、角色、故事线、文案风格 |

**关键决策记录格式**:
```markdown
| 决策项 | 决策内容 | 理由 | 影响范围 |
|--------|----------|------|----------|
| XP数值 | 170→190 | 与L03一致 | L01/L02 |
```

**质量检查清单**:
- [ ] 关键决策表格完整（决策项/内容/理由）
- [ ] 数据模型示例可直接用于 lesson.json
- [ ] 故事线有清晰的起承转合
- [ ] 与L03设计保持一致性

---

### Phase 3: Detail 详细设计

**负责 Agent**: UX-Designer + Content-Designer

**输入**:
- Phase 2 概念设计
- DESIGN_SYSTEM.md 设计规范

**产出物**:

| 文件 | 路径 | 内容要求 |
|------|------|----------|
| PRD文档 | `docs/design/prd/{代号}_prd.md` | 完整课程数据、UI规范、内容文案 |
| lesson.json | `courses/{课程号}/lesson.json` | 可直接使用的课程数据文件 |
| 文案资源 | `courses/{课程号}/content/` | 场景文案、提示文案 |
| 代码模板 | `courses/{课程号}/templates/` | 学生初始代码、参考答案 |
| 检查规则 | `courses/{课程号}/checks/` | 代码检查规则脚本 |

**PRD文档结构**:
```markdown
# PRD - {课程名}

## 1. 课程概览
## 2. Phase 1: 知识阶段
### 2.1 场景故事
### 2.2 概念卡片
### 2.3 测验题目（4道）
### 2.4 代码填空（4道）
## 3. Phase 2: 实践阶段
### 3.1 任务描述
### 3.2 步骤设计
### 3.3 代码模板
### 3.4 检查规则
## 4. Phase 3: 挑战阶段
### 4.1 Bug猎手描述
### 4.2 错误代码
### 4.3 渐进提示
## 5. UI设计规范
## 6. 徽章与XP配置
```

**质量检查清单**:
- [ ] lesson.json 语法正确可通过校验
- [ ] 测验题目有正确答案标注
- [ ] 代码填空有参考答案
- [ ] Bug猎手代码包含预设错误
- [ ] 渐进提示从模糊到具体

---

### Phase 4: Review 评审验证

**负责 Agent**: Reviewer + Validator

**输入**:
- Phase 3 PRD文档
- DESIGN_SYSTEM.md 设计规范

**产出物**:

| 文件 | 路径 | 内容要求 |
|------|------|----------|
| 评审报告 | `docs/design/review/{代号}_review.md` | 评分、问题清单、通过决策 |

**评审报告结构**:
```markdown
# 设计评审报告 - {项目名}

## 评分总览

| 维度 | 权重 | 得分 | 说明 |
|------|------|------|------|
| 教育价值 | 25% | 5/5 | ... |
| 游戏化 | 20% | 4/5 | ... |
| 用户体验 | 20% | 4/5 | ... |
| 技术可行 | 20% | 5/5 | ... |
| 一致性 | 15% | 4/5 | ... |
| **总分** | 100% | **X/5** | |

## 问题清单

### P0 阻塞性问题（必须解决）
- [ ] 问题描述 | 建议方案 | 负责人

### P1 重要问题（建议解决）
- [ ] 问题描述 | 建议方案 | 负责人

### P2 优化建议（可选）
- [ ] 问题描述 | 建议方案 | 负责人

## 评审结论

- [ ] 通过 - 可直接进入开发
- [ ] 有条件通过 - 需解决P0问题
- [ ] 不通过 - 需重新设计

## 签名
Reviewer: {名字}  Date: {日期}
```

**质量检查清单**:
- [ ] 5个维度都有评分
- [ ] 问题清单按P0/P1/P2分级
- [ ] 每个问题有明确的责任人
- [ ] 有明确的通过/不通过结论

## 3. 状态同步规范

### 3.1 MEMORY.md 更新时机

以下事件发生时，必须更新 `~/.claude/projects/.../memory/MEMORY.md`：

| 事件 | 更新内容 |
|------|----------|
| Phase N 开始 | 记录开始时间、派遣Agent |
| Phase N 完成 | 记录完成时间、产出物路径、关键结论 |
| 关键决策变更 | 更新决策表格，记录变更理由 |
| 问题发现 | 记录问题清单，标注优先级 |

### 3.2 WORK_STATE 文档

每次会话结束时，应在项目docs目录下创建当天的状态快照：

**路径**: `TeenagerCPlusPlusEduSystem/docs/WORK_STATE_{YYYYMMDD}.md`

**内容模板**:
```markdown
# 工作状态 - {日期}

## 今日完成
- [x] 任务1
- [x] 任务2

## 产出物
| 文件 | 路径 | 描述 |
|------|------|------|
| 文档1 | 完整相对路径 | 简要说明 |

## 下一步
- [ ] 待办任务1
- [ ] 待办任务2
```

## 4. 文件命名冲突处理

### 4.1 同名文件处理

当多个Phase涉及同一课程时：

**方案**: 使用时间戳区分
```
L01_L02_research_v1.md       # 初步调研
L01_L02_research_v2.md       # 补充调研
L01_L02_research_final.md    # 最终版本
```

**优先**: 尽量使用一个文件，通过版本历史追踪变更。

### 4.2 多课程合并设计

如 L01/L02 合并设计：

```
# 推荐命名
L01_L02_research.md          # 合并调研报告
L01_L02_concept.md           # 合并概念设计

# 分别细化
L01_prd.md                   # L01详细设计
L02_prd.md                   # L02详细设计
```
