# L01/L02 概念设计 - 故事设计 (Storyteller Agent)

## 一、世界观架构

### 1.1 核心世界观

**世界名**: C++魔法学院 (C++ Magic Academy)

**基本设定**:
- 魔法与编程同源，代码即咒语
- 学院有8个主要课程，对应8周学习
- 学员需要通过实践和挑战获得徽章
- 学院位于云端，连接着数字世界

**魔法体系**:
```
基础魔法: cout, cin (输入输出)
分支魔法: if-else (逻辑判断)
循环魔法: for/while (重复执行)
函数魔法: 代码复用
数组魔法: 数据存储
图形魔法: EasyX可视化
对象魔法: 类与结构体
终极魔法: 综合项目
```

### 1.2 学院地图

```
                    [云端之巅 - 终极挑战]
                          ↑
                    [对象殿堂 - L7]
                          ↑
                    [彩虹工坊 - L6: 图形]
                          ↑
                    [道具仓库 - L5: 数组] ← 当前
                          ↑
                    [技能圣殿 - L4: 函数]
                          ↑
                    [刷怪峡谷 - L3: 循环]
                          ↑
                    [智慧之门 - L2: 分支] ← 重构目标
                          ↑
[C++魔法学院大门] → [新手村 - L1: 你好C++] ← 重构目标
```

## 二、角色设定

### 2.1 小极 (Jí)

**基础信息**:
- 年龄: 13岁
- 性格: 热血、好奇、有点冒失、喜欢动手
- 特长: 想象力丰富，善于发现有趣的用法
- 弱点: 容易急躁，细节容易出错
- 口头禅: "让我试试！"

**学习风格**:
- 喜欢先动手，后理解
- 从错误中学习
- 需要具体的例子

**在故事中的作用**:
- 代表"实践中学习"的学员
- 提供学习中的常见错误
- 通过错误引出知识点

### 2.2 小灵 (Líng)

**基础信息**:
- 年龄: 13岁
- 性格: 冷静、细心、善于观察、喜欢思考
- 特长: 逻辑清晰，善于总结规律
- 弱点: 有时过于追求完美
- 口头禅: "让我想想..."

**学习风格**:
- 喜欢先理解，再实践
- 从原理出发
- 善于发现规律

**在故事中的作用**:
- 代表"理解后实践"的学员
- 提供对概念的清晰解释
- 通过总结帮助记忆

### 2.3 配角设定

**守门老法师 (L01)**:
- 慈祥的老者
- 负责接待新学员
- 第一句问候咒的传授者

**魔法教授 (L02)**:
- 严谨的中年法师
- 分支魔法课程的导师
- 擅长用猜数字解释if-else

**数据守护者 (L03)**:
- 神秘的仓库管理员
- 数组知识的引导者

## 三、L01 故事线设计

### 3.1 故事大纲

**标题**: 「你好，C++！」— 程序员的第一个魔法咒语

**故事弧**:
```
起 (场景故事):
小极和小灵收到C++魔法学院的入学通知书
↓
来到学院大门，神秘符文漂浮在空中
↓
承 (知识学习):
守门老法师解释"问候咒"的5个步骤
↓
小极尝试修改咒语，输出自己的名字
↓
转 (实践挑战):
编写个性化问候程序
↓
合 (挑战收获):
发现"语法小偷"偷走的符号
↓
修复代码，获得hello_master和bug_hunter徽章
```

### 3.2 详细场景

**场景1: 魔法学院的入门咒语 (知识阶段-场景)**

> 清晨，阳光透过云层，照耀在一座悬浮于空中的宏伟建筑上。
>
> 小极紧紧攥着入学通知书，眼睛闪闪发光。
> "终于到了！C++魔法学院！"
>
> 身旁的小灵认真地读着录取信：
> "在这里，每一行代码都是一个魔法咒语..."
>
> 大门缓缓打开，一位白胡子老法师站在门口，微笑着说：
> "欢迎来到魔法学院，年轻的学徒们。
> 在正式开始学习之前，你们要先学会程序员的第一个咒语——向世界问好。"
>
> 老法师挥动法杖，空中浮现出发光的代码：
> ```cpp
> #include <iostream>
> using namespace std;
> 
> int main() {
>     cout << "Hello, World!" << endl;
>     return 0;
> }
> ```
> "这就是最基础的'问候咒'，让我们一行一行理解它的含义..."

**关键元素**:
- 代入感: 收到通知书、来到学院
- 神秘感: 悬浮建筑、发光符文
- 学习目标明确: 第一个咒语

---

**场景2: 代码实践中的插曲 (实践阶段-过渡)**

> "现在轮到你们了，"老法师说，
> "试着修改这段咒语，让它向世界介绍你们自己。"
>
> 小极立刻冲上前："让我试试！"
> 他快速写下：
> ```cpp
> cout << "你好，我是小极！" << endl;
> cout << "欢迎来到C++魔法世界！" << endl;
> ```
> "哈哈，成功了！"
>
> 小灵在一旁提醒："别忘了加上你的幸运数字哦。"
> "对哦！"小极又加了一行：
> ```cpp
> cout << "我的幸运数字是：7" << endl;
> ```
> "完美！"

**关键元素**:
- 角色个性: 小极冲动尝试，小灵细心提醒
- 任务明确化: 三段输出
- 成就感: 立即看到结果

---

**场景3: 语法小偷的阴谋 (挑战阶段-冲突)**

> "等一下！"老法师突然严肃起来，
> "小极，你的代码里好像有什么东西不对劲..."
>
> 小极困惑地检查代码："哪里有错？运行很正常啊..."
>
> 老法师指向空中的代码幻影：
> "看！这里有个'语法小偷'！"
>
> 只见一个小黑影从代码中窜出，手里拿着几个发光的符号。
> "那是我的分号！"小极大叫。
> "还有我的花括号！"小灵也发现了异常。
>
> 老法师解释道：
> "语法小偷专门偷走重要的符号，让咒语失效。
> 你们需要找出代码中缺失的符号，把小偷抓出来！"
>
> 小极握紧拳头："交给我吧！"

**关键元素**:
- 冲突引入: 语法小偷的意外出现
- 角色互动: 两人合作抓Bug
- 游戏化: Bug猎手包装

---

## 四、L02 故事线设计

### 4.1 故事大纲

**标题**: 「分支魔法」— 猜数字的智慧之门

**故事弧**:
```
起 (承接L1):
进入学院后的第一堂课
↓
来到智慧之门前
承 (知识学习):
魔法教授讲解分支魔法
↓
小极猜50，门给出提示
↓
理解if-else判断逻辑
转 (实践挑战):
编写完整猜数字游戏
↓
小极编写，小灵测试
合 (挑战收获):
发现==和=的逻辑陷阱
↓
修复Bug，获得branch_master徽章
```

### 4.2 详细场景

**场景1: 智慧之门的考验 (知识阶段-场景)**

> L01通过后，小极和小灵正式成为C++魔法学院的学员。
>
> 今天的第一堂课是"分支魔法"——教会程序如何根据不同情况做出选择。
>
> 他们来到教学楼门口，一扇巨大的石门挡在面前。
> 门上刻着三行发光的文字：
> ```
> "请输入一个0-100之间的数字
>  如果猜对了，门就会打开
>  如果猜错了，我会告诉你偏大还是偏小"
> ```
>
> 小极走上前，自信地输入了50。
>
> 门上的符文开始闪烁：
> "50... 不对哦，但是你已经很接近了！"
> "提示：你要找的数字比50大"
>
> "这是怎么做到的？"小极惊讶地问。
>
> 一位穿着蓝袍的魔法教授从门后走出：
> "这就是分支魔法的威力！程序可以根据不同情况给出不同提示。
> 让我来解释这其中的奥秘..."
>
> 教授用法杖在空中画出代码结构：
> ```cpp
> if (猜对了) {
>     门打开！
> } else if (猜大了) {
>     提示：太大了
> } else {
>     提示：太小了
> }
> ```

**关键元素**:
- 承接: 通过L01正式入学
- 悬念: 猜数字游戏自然引入
- 目标: 学会分支魔法

---

**场景2: 游戏中的争论 (实践阶段-过渡)**

> "小极，你来编写猜数字游戏，"教授说，
> "小灵，你来测试，看看能不能猜中。"
>
> 小极开始编写代码：
> "首先，生成随机数...然后获取输入...然后用if判断..."
>
> 小灵在一旁看着：
> "这里应该用双等号==，不是单等号=。"
>
> "我知道啦，让我先写完！"
>
> 代码终于写完了，小灵开始测试：
> "我猜... 75！"
>
> 程序输出："太大了！"
> "那我猜30！...太小了！"
> "58？太大了..."
> "50？太大了..."
> "45？太小了..."
> "48？...对！门开了！"
>
> 教授微笑着点头：
> "很好，你们掌握了分支魔法的核心。
> 但是...你们真的完全理解了吗？"

**关键元素**:
- 角色互动: 编程与测试分工
- 错误自然出现: == vs =的伏笔
- 成功体验: 游戏成功运行

---

**场景3: 逻辑陷阱的发现 (挑战阶段-冲突)**

> 小灵仔细看着代码，突然皱起眉头：
> "小极，这里...你为什么用单等号？"
>
> 她指着这一行：
> ```cpp
> if (guess = secret) {
> ```
>
> "这不是比较，这是赋值！
> 它的意思是'把secret的值给guess'，而不是'guess等于secret吗'。"
>
> 小极挠头："可是程序运行正常啊..."
>
> "让我来测试一个特殊情况，"小灵说。
>
> 她修改了测试用例，运行结果让所有人都惊讶了...
>
> 教授严肃地说：
> "这就是'逻辑陷阱'——它平时不会显露，但在特定情况下会造成大麻烦。
> 很多初学者都会犯这个错误。你们需要彻底理解
> '=' 是赋值，'==' 才是比较！"
>
> 小极恍然大悟：
> "原来如此！让我把错误改过来..."

**关键元素**:
- 深层次的陷阱: 不只是符号，是概念
- 小灵发现: 细心的优势
- 教育价值: 错误分析比正确答案更重要
