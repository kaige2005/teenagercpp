# Task with Validation Skill - 带验证的任务创建

创建任务时自动包含验证子任务，确保代码完成时经过充分测试。

## 用法

```
/task-v <任务标题> [options]
```

## 自动包含的验证子任务

每个创建的任务将自动包含以下子任务:

1. **实现** (implementation)
   - 核心代码编写
   - 单元测试编写 (TDD模式)

2. **编译验证** (compile-check)
   - 项目可编译通过
   - 无编译器警告
   - 依赖项正确引用

3. **运行时测试** (runtime-test)
   - 功能按预期工作
   - 边界条件处理
   - 异常场景测试

4. **集成验证** (integration-check)
   - 与其他模块协同工作
   - 数据流正确
   - UI渲染正常

5. **文档更新** (documentation)
   - 代码注释更新
   - README/CHANGELOG更新
   - 用户文档更新

## 选项

- `--no-compile`: 跳过编译验证子任务
- `--no-runtime`: 跳过运行时测试子任务
- `--no-docs`: 跳过文档更新子任务
- `--release`: 添加发布检查子任务

## 示例

```
/task-v 实现L03挑战阶段
/task-v 修复Dock布局问题 --release
/task-v 添加代码填空功能 --no-docs
```

## 验证标准

在标记子任务完成前，必须确认:

### 编译验证
- [ ] 项目能在本地编译成功
- [ ] 无阻碍性编译错误
- [ ] 所有依赖项已正确包含

### 运行时测试
- [ ] 功能在IDE中可运行
- [ ] 主要功能路径已测试
- [ ] 至少一个边界条件已验证

### 集成验证
- [ ] 与现有功能无冲突
- [ ] 数据持久化正常 (如涉及数据库)
- [ ] UI渲染符合预期 (如涉及界面)
