# Context-Aware Assistant - 场景感知助手

根据用户当前活动和对话上下文，自动建议合适的工具和流程。

## 触发规则

### 场景1: 创建新功能/修复Bug
**触发条件**: 用户说"实现..."、"修复..."、"添加...功能"、"bug"
**自动建议**:
```
检测到功能开发场景。建议:
1. 使用 /tdd 进行测试驱动开发
2. 使用 /task-v 创建带验证的任务

需要我帮您启动TDD流程吗?
```

### 场景2: 标记任务完成
**触发条件**: 用户使用"完成了"、"标记为完成"、"任务做完了"
**自动检查**:
- 该任务是否有"编译验证"子任务?
- 该任务是否有"运行时测试"子任务?
**自动提示**:
```
即将标记任务完成。请确认:
□ 已实现功能代码
□ 已通过编译验证
□ 已完成运行时测试
□ 已测试边界条件

或者运行 /precheck 自动验证?
```

### 场景3: 准备发布/打包
**触发条件**: 用户说"发布"、"打包"、"出beta"、"正式版"
**自动建议**:
```
检测到发布场景。建议执行 /release 流程:
- 自动检查GitHub CLI认证
- 验证所有DLL依赖
- 运行功能测试
- 创建GitHub Release

要启动发布流程吗? 请输入版本号 (如 v1.2.0-beta.8)
```

### 场景4: 代码生成/编写C#
**触发条件**: 用户要求生成C#代码、编写.NET代码
**自动注入**:
```
⚠️ .NET Framework 4.8 兼容性提醒:
- 不要使用 value.GetValueOrDefault()
- 使用 bool.TryParse 替代 bool.Parse
- 注意空引用检查

需要 /tdd 流程确保代码质量吗?
```

### 场景5: 遇到Bug/错误
**触发条件**: 用户报告错误、异常、崩溃
**自动建议**:
```
检测到问题排查场景。建议:
1. 使用 systematic-debugging Skill 分析根因
2. 修复后使用 /precheck 验证
3. 创建回归测试防止复发

启动系统化调试流程?
```

### 场景6: 课程/UI设计
**触发条件**: 用户讨论UI、界面、课程设计
**自动建议**:
```
检测到UI设计场景。建议:
- 使用 frontend-design Skill 创建高保真设计
- 或使用 superpowers:writing-plans 规划架构

需要设计课程交互界面吗?
```

## 实现机制

### 对话分析
在每次用户输入后，分析关键词：

```csharp
// 伪代码
var keywords = new Dictionary<string, Scene> {
    ["实现|修复|添加功能"] = Scene.FeatureDevelopment,
    ["完成了|标记完成"] = Scene.TaskCompletion,
    ["发布|打包|beta|版本"] = Scene.Release,
    ["生成.*代码|写.*C#"] = Scene.CodeGeneration,
    ["错误|异常|崩溃|bug"] = Scene.Debugging,
    ["UI|界面|设计|外观"] = Scene.UIDesign
};
```

### 建议呈现
不是强制打断，而是**上下文提示**：
- 用 💡 图标标示建议
- 提供一键执行的快捷方式
- 用户可以说"不用"跳过

### 学习用户习惯
- 如果用户多次拒绝某类建议，降低该场景的建议频率
- 记录用户接受的建议，优化推荐准确度

## 使用示例

**对话1 - 自动触发TDD**
```
用户: 我需要实现L04的课程导入功能
Claude: 💡 检测到功能开发场景。建议:
      1. 使用 /tdd 进行测试驱动开发
      2. 使用 /task-v 创建带验证的任务
      
      要启动TDD流程吗? [是/否]

用户: 是
Claude: [启动 /tdd 流程]
```

**对话2 - 完成前验证**
```
用户: 我把代码写完了，标记任务完成
Claude: ⏸️ 完成前检查清单:
      □ 编译通过
      □ 运行时测试
      □ 边界条件
      
      运行 /precheck 自动验证? [运行/跳过]
```

**对话3 - 发布提醒**
```
用户: 准备发布v1.2.0正式版
Claude: 🚀 检测到发布场景。
      
      将执行 /release v1.2.0 流程:
      - 清理bin/obj
      - 编译验证
      - DLL依赖检查
      - 功能测试
      - 创建GitHub Release
      
      GitHub CLI已认证 ✓
      开始发布流程? [开始]
```

## 与现有Skill整合

这个助手不替代现有Skill，而是:
- **发现场景** → 建议合适的Skill
- **降低门槛** → 用户不需要记忆命令
- **确保执行** → 关键环节自动提醒
