# Claude 响应模式 - 场景化自动建议

## 核心原则

**用户不需要记住命令，只需要自然表达意图。**

我在对话中监测以下模式，主动提供合适的工具建议。

---

## 场景1: 功能开发 (Feature Development)

### 触发信号
```
用户说: "实现..." / "添加...功能" / "做..." / "搞定..." 
        / "新功能" / "开发..." / "写一个..."
```

### 我的响应
```
💡 开发模式

建议流程:
1. /task-v <功能名称>    → 创建结构化任务
2. /tdd <功能描述>      → 测试驱动开发 (推荐)

选择: [启动TDD] [仅创建任务] [直接开始]

提示: 这将自动生成:
- 实现代码 ✍️
- 编译验证 ✅
- 运行时测试 🧪
- 文档更新 📝
```

### 执行
如果用户说"启动TDD"或"好"，立即执行 `/tdd` 流程。

---

## 场景2: 任务完成验证 (Task Completion)

### 触发信号
```
用户说: "完成了" / "搞定了" / "做完了" / "可以了"
        / 要求 "标记完成" / "update task"
```

### 我的响应
```
⏸️ 完成任务前检查

已检测到任务完成意图。执行验证:

□ 编译验证      (运行 /precheck quick)
□ 运行时测试    (手动确认或自动测试)
□ 边界条件测试  (至少1个场景)

/precheck 结果: [等待执行]

建议:
- 说"检查"运行预检查
- 说"完成"跳过检查直接标记
- 说"先不测"暂不完成
```

### 执行
- 用户说"检查" → 运行 `/precheck`
- 用户说"完成" → 确认清单后标记完成
- 发现问题 → 建议修复后再完成

```
用户说: "发布" / "出版本" / "打包" / "beta" / "正式版"
        / "v1.x.x" / "release" / "上线"
```

### 我的响应
```
🚀 发布模式

检测到发布意图。建议执行标准化发布流程:

/release <版本号> [--beta]

将自动执行:
├─ 预检查: GitHub CLI, 工作目录

或选择: [直接开始] [先检查] [跳过测试]
```

### 执行
如果用户提供版本号或说"开始"，立即执行 `/release`。

## 场景4: 代码生成 (Code Generation)

### 触发信号
```
用户说: "生成代码" / "写个C#" / "实现类" / "添加方法"
        / "给我写..." / "代码怎么写"
        涉及: WinForms, C#, .NET, 数据库操作
```

### 我的响应
```
⚠️ .NET Framework 4.8 兼容性提示

生成代码时将自动应用以下约束:

❌ 避免使用:
   - value.GetValueOrDefault()  ← 4.8不支持
   - bool.Parse(string)         ← 可能异常
   - ??= 操作符                 ← C# 8.0+ 特性

✅ 使用替代:
   - value ?? defaultValue
   - value.HasValue ? value.Value : defaultValue
   - bool.TryParse(string, out result)
   - 单独赋值: if (x == null) x = y;

额外检查:
□ 空引用检查 (UI控件、数据库结果)
□ UI线程操作 (InvokeRequired检查)
□ 资源释放 (using语句)

建议配套: /tdd 流程确保代码质量
```

### 执行
生成代码时自动应用约束，生成后询问是否启动TDD。

## 场景5: 问题排查 (Debugging)

### 触发信号
```
用户说: "出错了" / "报错" / "崩溃" / "异常" / "不工作"
        / "bug" / "失败" / "null引用" / "空指针"
        / "为什么...不"
```

### 我的响应
```
🔧 调试模式

检测到问题。建议系统化排查:

superpowers:systematic-debugging
       ↓
1. 复现问题
2. 收集信息 (日志/堆栈/环境)
3. 隔离变量
4. 形成假设
5. 验证修复

快捷选项:
- [常见.Null引用问题] → _lblPhaseStatus等控件检查
- [常见.Dock布局问题] → 序列化/初始化检查
- [常见.SQLite问题] → 平台DLL检查
- [完整分析] → 启动systematic-debugging

或提供: 错误信息 / 截图 / 复现步骤
```

### 执行
根据问题类型提供针对性建议，必要时调用 `systematic-debugging`。

## 响应优先级

当多个模式同时触发时，按优先级响应：

1. **问题排查** (P0) - 阻断性问题优先
2. **发布活动** (P0) - 关键操作需谨慎
3. **任务完成** (P1) - 质量保证
4. **功能开发** (P1) - 标准流程
5. **代码生成** (P2) - 约束提醒
6. **UI设计** (P2) - 增值建议

---

## 用户控制

### 快捷短语
| 用户说 | 含义 |
|--------|------|
| "好" / "执行" / "开始" | 接受建议并执行 |
| "不用" / "跳过" / "暂时不" | 忽略本次建议 |
| "总是这样" / "记住" | 该场景始终自动执行 |
| "别烦我" / "安静模式" | 该场景不再建议 |

### 记忆用户偏好
- 如果用户3次拒绝某场景建议 → 减少提示频率
- 如果用户说"总是这样" → 该场景自动执行不询问
- 用户可随时说"恢复建议"重新启用
